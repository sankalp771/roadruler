## [15:25:00] Task: Frontend ↔ Backend ↔ AI Live Integration Wiring

### 1. Objective & Architectural Rationale
- Wired the React frontend to the real FastAPI backend so the citizen report flow hits the live API (and through it, the Celery/YOLO AI pipeline) instead of silently failing and faking success.
- Three gaps closed: (a) no Vite dev proxy, so relative `/api/...` calls never left the Vite server; (b) no Clerk JWT attached to the complaint POST, so backend auth would reject every submission; (c) `VITE_CLERK_PUBLISHABLE_KEY` was not configured, so real Clerk sign-in was never active — only the localStorage demo login.
- Removed the "optimistic fallback" in `ReportIssue` that showed a fake success toast + mock complaint ID when the API call failed; failures now surface the real backend error. Rationale: the fallback would mask genuine integration failures during the live demo.

### 3. Implementation Details
- `getToken()` in `SmartAuthInner` returns `clerkAuth.getToken()` only when a real Clerk session exists; the localStorage demo login deliberately returns `null` so it can never silently submit unauthenticated requests.
- Success toast now shows the real backend response status (`PROCESSING`), and navigation uses the real complaint UUID returned by the API.
- Dev proxy uses `changeOrigin: true`; no CORS configuration needed on the backend for local development.
